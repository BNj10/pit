# PIT Enroll

Next.js application with Supabase CLI for local development.

## Prerequisites

- Node.js 20.9 or newer and pnpm (the setup was verified with pnpm 11).
- Docker Desktop running with Linux containers.

The Supabase CLI is pinned as a project development dependency. A global install,
Supabase account, and hosted project are not required for local development.

## Local development

Run from the project root:

```sh
pnpm install
pnpm supabase:start
```

The first start downloads the Docker images and can take several minutes.
The committed `supabase/config.toml` is already initialized for this project.
This project uses ports 55320-55329 (and 8084 for the Edge Functions inspector)
to avoid conflicts with another local Supabase project using the default ports.
Optional log analytics is disabled to reduce Docker memory use.

Copy `.env.example` to `.env.local` (PowerShell: `Copy-Item .env.example .env.local`),
then copy the **Publishable** key from `npm run supabase:status` into
`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` and the **Secret** key into
`SUPABASE_SECRET_KEY`. The URL is already set to the local API. The secret key is
used only on the server, to resolve student ID logins. Restart Next.js after
changing environment variables.

### Signing in

Every page except the login and password-reset pages requires a session. Accounts
are created by the Administrator (sign-up is disabled). A database trigger gives each
new user a `public.profiles` row with the `student` role; change `role` to
`department-chair` or `dean` for staff. Students can log in with their email, or with
their student ID once they have set it through `set_student_id()`.

`supabase/seed.sql` creates synthetic local accounts, all with the password
`Preview-Pass-2026`:

| Role | Email | Student ID |
| --- | --- | --- |
| Student | student.preview@pit-enroll.test | 99-0000-001 |
| Department Chair | chair.preview@pit-enroll.test | — |
| Dean | dean.preview@pit-enroll.test | — |

The seed runs on the first `supabase:start` and on `db:reset`. To add the schema to an
existing local database without deleting its data, run
`npx supabase migration up --local`, then create accounts in Supabase Studio.

### Hosted project

The deployed site uses the hosted `pit-enroll` Supabase project. Its schema was first
created in the dashboard; `supabase/migrations/20261123160000_hosted_baseline.sql`
records it and is marked as applied there. Add schema changes as new migrations and
apply them with `npx supabase db push --linked` after `npx supabase link`.
The deployment needs `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`,
and `SUPABASE_SECRET_KEY` from the hosted project.

```sh
pnpm dev
```

| Service | Local address |
| --- | --- |
| Application | http://localhost:3000 |
| Supabase API | http://127.0.0.1:55321 |
| Supabase Studio | http://127.0.0.1:55323 |
| Test email inbox | http://127.0.0.1:55324 |
| PostgreSQL | `postgresql://postgres:postgres@127.0.0.1:55322/postgres` |

Auth redirects accept the local application on port 3000 using either `localhost`
or `127.0.0.1`. Email confirmation is disabled by default for local development.
Email generated by the local stack can be inspected in the test email inbox.

## Database workflow

```sh
# Create a timestamped migration, then edit its SQL in supabase/migrations/.
pnpm db:migration create_initial_schema

# Recreate the LOCAL database, apply migrations, and run supabase/seed.sql.
# This deletes existing local database data.
pnpm db:reset

# Check the running local database for SQL errors.
pnpm db:lint

# Show service URLs and local keys.
pnpm supabase:status

# Stop services while preserving local data for the next start.
pnpm supabase:stop
```

Run additional CLI commands with `pnpm exec supabase <command>`.
Commit configuration, migrations, and seed data. Local environment files and
Supabase temporary state are ignored by Git. Keep secret/service-role keys out
of `NEXT_PUBLIC_*` variables.

## Validation

